## docker-256

- **Repository / BugID:** `moby/moby` / `moby#256`.
- **Dataset / fixing commit:** [`58befe3081726ef74ea09198cd9488fb42c51f51`](https://github.com/moby/moby/commit/58befe3081726ef74ea09198cd9488fb42c51f51).
- **Pre-fix checkout:** [`1d6929c8bc6cbc5ad63dce083869460b6bb377ad`](https://github.com/moby/moby/commit/1d6929c8bc6cbc5ad63dce083869460b6bb377ad), the first parent of the fixing commit.
- **Source inspected:** [`archive.go`](https://github.com/moby/moby/blob/1d6929c8bc6cbc5ad63dce083869460b6bb377ad/archive.go).
- **Inventory reference:** `blocking` row 18; reproduced flag 1; patch size 8; cause `MessagingLib`.
- **Upstream symptom:** CmdStream can deadlock when a child fills stderr while the parent is still draining stdout.
- **Proposed trigger:** Start /bin/sh with `dd if=/dev/zero bs=1k count=1000 of=/dev/stderr; echo hello`, pass the command to CmdStream, and drain the returned reader. The old function reads stdout to EOF before stderr; the child cannot reach echo/exit once stderr is full.
- **Success criterion and fixed control:** The drain must reach EOF on the fixed version. On the buggy version, use an external timeout and capture the child/parent pipe wait state. Confirm the process started successfully before classifying a timeout.
- **Estimated effort:** Half a day.
- **Compatibility / validity risk:** The 2013 Docker tree predates modules; isolate the unchanged CmdStream function with its standard-library imports if whole-tree compilation fails, and label that run as an extracted reproducer. Shell and pipe behavior require Linux.
- **Execution status:** Not built or run by this team.
- **Skeleton preparation target:** 20-30 minutes: add the upstream large-stderr regression input, a reader-drain completion marker, and an external timeout wrapper; preserve the original I/O order.

## docker-8909

## etcd-6937

- **Repository / BugID:** `etcd-io/etcd` / `etcd#6937`.
- **Dataset / fixing commit:** [`91ff6f30b50a14158ec10cdd24836d775a336f52`](https://github.com/etcd-io/etcd/commit/91ff6f30b50a14158ec10cdd24836d775a336f52).
- **Pre-fix checkout:** [`2509e7ad2cc0daaa9afc629ebdb9c56429de9ea1`](https://github.com/etcd-io/etcd/commit/2509e7ad2cc0daaa9afc629ebdb9c56429de9ea1), the first parent of the fixing commit.
- **Source inspected:** [`proxy/grpcproxy/watch_broadcast.go`](https://github.com/etcd-io/etcd/blob/2509e7ad2cc0daaa9afc629ebdb9c56429de9ea1/proxy/grpcproxy/watch_broadcast.go).
- **Inventory reference:** `blocking` row 44; reproduced flag 1; patch size 3; cause `Mutex`.
- **Upstream symptom:** watchBroadcast methods deadlock by reacquiring their own RWMutex.
- **Proposed trigger:** In a package-level harness, construct a watchBroadcast with an empty receivers map and invoke bcast with a valid empty WatchResponse. bcast takes the write lock and then calls size(), which takes RLock. An alternative trigger calls delete on an existing watcher before empty() repeats the lock acquisition.
- **Success criterion and fixed control:** A completion marker after bcast is absent on the buggy revision and present on the fixed revision. Capture the nested Lock/RLock stack; avoid receiver-send blocking by using an empty map.
- **Estimated effort:** Half a day.
- **Compatibility / validity risk:** The dataset labels this Mutex even though the source uses RWMutex; preserve the dataset label and explain the implementation detail. Historical protobuf/prometheus dependencies may require pinning.
- **Execution status:** Not built or run by this team.
- **Skeleton preparation target:** 15-30 minutes: construct the minimal receiver map and response, call bcast from the original package, and mark completion. If dependencies block compilation, write the harness before resolving them; do not claim a successful run.
